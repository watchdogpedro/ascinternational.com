Do the page names matter?

"Should we rename the new site's pages to match the old ones?"
No — identical page names are not a Google ranking factor. What carries your rankings forward is a 301 redirect.

Google's own migration documentation states it plainly: "301 and other permanent redirects don't cause a loss in PageRank." A 301 is a permanent "this page moved here" instruction. Set one up for every old address and Google quietly transfers years of ranking power to the new page — whatever you choose to name it.

The redirect — not a matching name — is what moves the rankings. Menu wording like "Solutions" vs "Products" is purely a branding choice; Google ranks URLs, not menu labels.

The one scenario that wrecks it: wiping the old WordPress site with no redirects. Old URLs return "page not found," Google drops them, and the documented result is a 20–60% traffic loss within about two weeks. That outcome is the downside of doing it wrong — and it is entirely preventable.

ASC International — SEO Migration StrategyThe Plan
Recommendations

The plan, in priority order

1

Build the redirect map before launch

The single most important step. Pair every old indexed URL with its closest new page. This is the safety net that carries your rankings across.

2

Reuse the good old URLs where it's easy

Paths like /smt-inspection/solder-paste-inspection/ are already keyword-rich and proven. A URL you keep needs no redirect at all — zero risk. Only change one where there's a real reason.

3

Never funnel everything to the homepage

Each old page redirects to its real match. Homepage-dumping old URLs is a top migration mistake that quietly drains ranking power.

4

For AI search, skip the gimmicks

Google's official 2026 stance: "optimizing for generative AI search is still SEO." No llms.txt, no special markup. To get cited by ChatGPT & AI Overviews, open each page with a plain-English answer in the first ~150 words, then use clear headings, FAQ Q&A, and spec tables.

5

Lean into the single-topic focus

A site that's only about solder paste inspection & AOI builds exactly the "topical authority" Google rewards and gives AI engines clean expert passages to quote. Redirect old off-topic articles into relevant SPI/AOI content rather than carrying them over.

6

Keep schema — but right-size it

Organization, Product, FAQPage and BreadcrumbList markup earn rich results in classic Google. They're helpful but not required for AI citation — there, content quality is the real lever.

ASC International — SEO Migration StrategyQuick Reference
Cheat Sheet

Do this. Not that.

✓ DO

  • Build the complete redirect map first
  • Reuse proven, keyword-rich old URLs
  • Server-side render so Google sees content without JavaScript
  • Give every page a unique title + meta description
  • Submit the new sitemap in Search Console
  • Keep the old site reachable so redirects can fire
  • Watch for 404 errors for ~30 days after launch

✕ DON'T

  • Wipe the old site with no redirects in place
  • Redirect everything to the homepage
  • Change URLs with no real reason
  • Rely on llms.txt or AI-specific gimmicks
  • Let pages load only via client-side JavaScript
  • Strip out the page titles & descriptions Rank Math set
  • Take the old domain offline too early
🤖

Getting cited by AI

AI engines pull and quote self-contained passages, not whole pages. Front-load the answer, write in clear Q&A blocks, and use your precise industry terms — "SPI," "AOI," "solder paste inspection." Jargon helps here.

⚙️

The Next.js trap to avoid

The classic replatform failure is content that only appears after JavaScript runs — crawlers may miss it. Render pages on the server, and generate a real sitemap.xml and robots.txt.

Bottom line: this move is safe to make — if the redirect map exists before you flip the switch. The risk isn't the new site; it's launching without that map.
